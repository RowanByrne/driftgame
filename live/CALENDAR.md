# Calendar

What's coming and when: updates, live events and timed releases (docs/workflow/RELEASING.md "Timed releases"), each with its game page event (RELEASING.md "Game page events"). Rocco's Updates view shows these cards on a calendar; the user adds and edits them there, and agents edit them here. Replace each prompt with the answer.

- **One card per update.** An in-game release and its game page event share a card, so their times can't drift apart.
- **Times in UTC.**
- **Publish before the time.** Content that opens on a timer ships closed in an earlier publish; note which release carries it on its card.
- **Record game page text word for word** below, as published.

**Auto-queue game page events:** 14 days ahead

## Upcoming

> One card per update, soonest first, in this form. Rocco reads and writes them, so keep the marker line and the field names:
>
> - A marker line `<!-- update: <id> -->`, with a short id like `pet-evolution`, then the update's name as a `###` heading.
> - **When:** the day, `YYYY-MM-DD`, and its time in UTC when it has one: `2026-11-14 17:00 UTC`.
> - **Kind:** Update, Live event or Timed release.
> - **Game page event:** Not yet, Queued (T-012), Drafted, Scheduled, Live, Over, or None when it shouldn't get one.
> - **Event id:** once the event exists on Roblox. **Card image:** the card the user picked. **Release:** for timed content, its release id and the publish that carries it.
> - Then the user's notes, in their words: what's in it, and anything the event should say.
